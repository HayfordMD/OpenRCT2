==============================================================
OpenRCT2 AI Simulation Integration - Project State & Summary
==============================================================

## 1. What We Learned
- **Headless vs Visual Engine:** The OpenRCT2 headless engine (`openrct2-cli.exe`) fundamentally simulates the game loop without graphics at a much higher speed, but we can also inject an AI bridge into the visual client (`openrct2.exe`) by specifying a valid Steam/GOG `game_path` in `config.ini`.
- **String Parsing Bugs:** Configurations in OpenRCT2 (`config.ini`) parse backslashes strictly (e.g. treating `\S` as simply `S`). Windows paths must use forward slashes `/` or double backslashes `\\` to load correctly.
- **Construction Logic:** Ride construction mathematically breaks down into four discrete C++ Engine Actions:
  1. `ridecreate` (allocating memory/metadata)
  2. `trackplace` (spawning physics tiles; Flat Rides are technically just 1 track piece)
  3. `rideentranceexitplace` (spawning the 2 separate entry/exit stations)
  4. `ridesetstatus` (setting operating mode to 1/Open)
- **Extensibility:** The game allows an external Python server to seamlessly replace the user interface using a bidirectional TCP Socket via an `ai_bridge.js` plugin payload.

## 2. What We Have Done
- **AI Brain Link:** Built a lightweight Python TCP Server (`ai_server.py`) and a Javascript Client Plugin (`ai_bridge.js`) that communicate every single in-game day to exchange financial telemetry and game state (Park Value, Guests, Cash).
- **Automated Workflow Script:** Wrote a `start-everything.bat` script that simultaneously spawns the Python server and the OpenRCT2 Visual Client on the custom `ai_test_park.SC6` scenario.
- **Baseline Construction Hook:** Wrote a sequential automated construction cycle in JS that automatically spawns a Merry-Go-Round on an empty map when the AI first connects, guaranteeing immediate financial activity for the RL model to observe.

## 4. Planned Next Steps (Phase 3)
1. **Tooling Integration:** Hook up a modern Python AI training library (like `stable-baselines3`) to our existing `OpenRCT2Env.py`.
2. **Algorithm Implementation:** We plan to instantiate a Proximal Policy Optimization (PPO) or Deep Q-Network (DQN) model that will utilize the Gymnasium `step()` interface to take discrete actions.
3. **Reward Architecture Expansion:** The reward function in `OpenRCT2Env.py` needs to be aggressively tailored to maximize long-term park capitalization over thousands of ticks rather than short-term spikes.
4. **Action Space Expansion:** Currently, our action space spans 0-7, mapped strictly to baseline behaviors. We will expand the JS layer to decode X,Y coordinates dynamically passed from the Python engine so the AI can decide exactly *where* to place ride infrastructures.
